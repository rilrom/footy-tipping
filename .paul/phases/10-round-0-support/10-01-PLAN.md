<objective>
## Goal
Allow navigation to Round 0 in the Tips and Results pages so AFL's Round 0 can be tipped and viewed.

## Purpose
AFL introduced Round 0 in the 2026 season. The Squiggle API provides game data for it. Currently the round navigator in both Tips and Results uses `round <= 1` as its lower boundary, which prevents navigating to Round 0. Changing the boundary to `round <= 0` is the only change required.

## Output
- Tips.tsx and Results.tsx updated with correct round navigation lower boundary
</objective>



<task type="auto">
  <name>Fix round navigation lower boundary in Tips and Results</name>
  <files>src/pages/Tips.tsx, src/pages/Results.tsx</files>
  <action>
    In both files, the back navigation arrow has two places that use `1` as the lower round boundary:
    1. The `disabled` prop: `disabled={round === null || round <= 1}`
    2. The `onClick` guard: `if (round !== null && round > 1)`

    Change both occurrences in both files:
    - `round <= 1` → `round <= 0`
    - `round > 1` → `round > 0`

    This allows Round 0 to be the minimum navigable round.

    Do NOT change the `isLocked = roundLocked || roundOffset < 0` logic in Tips.tsx — viewing a past round (negative offset from current) should remain locked, which is correct behaviour even when current round is 0.
  </action>
  <verify>
    TypeScript build passes: `npm run build` exits without errors.
    Visually confirm in browser: with currentRound=1, back arrow navigates to Round 0 and then disables.
  </verify>
